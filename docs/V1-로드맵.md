# Screen V1 로드맵 (README 7·8단계)

2026-09-24 정리. 화면(1~6단계)은 이미 있다. 이 문서는 **남은 7단계(채점·후속 질문 AI)와 8단계(저장)** 를 어디까지 하면 V1 인지와 순서만 정한다. 이 순서 밖의 기능은 V1 이 끝난 뒤에 논의한다.

## V1 문장

> Hire 에서 AI 1차 면접을 보내기로 한 후보자가 링크를 열어 **질문마다 캠 앞에서 답을 녹화**하면, Screen 이 말을 글로 받아 적어 평가 기준대로 **문항별 점수와 근거가 된 발언 원문**을 남기고(표정·목소리 톤은 채점하지 않는다), 담당자는 TalentCore 계정으로 들어가 영상·받아 적은 글·점수를 검토하고 그 결과를 **Hire 후보자 상세**에서 본다. 합격·불합격은 언제나 사람이 Hire 에서 정한다. 글 면접은 공고별 선택 옵션으로 남긴다.

**2026-09-26 변경(사용자 결정):** V1 을 채팅 면접에서 **녹화 영상 면접**으로 바꿨다. 국내 시장(역검·뷰인터HR)은 영상이 기본이라 글만으로는 비교에서 떨어진다. 대신 HireVue 가 비판받은 표정 분석은 하지 않고 **말한 내용만** 채점한다 — 이것이 차별점(근거가 보이는 점수 + 한국 법 대응)과 이어진다. 지금까지 만든 채팅 면접(SC1·SC4)은 그대로 '글 면접' 옵션이 된다.

## 누가 무엇을 갖나 (제품 소유권)

| 무엇 | 주인 | 이유 |
| --- | --- | --- |
| 계정·로그인 | **Core** | Hire·Grow 와 같은 TalentCore 계정(SSO). Screen 에 계정 표를 따로 만들지 않는다. |
| 후보자·전형 단계·합불 판정 | **Hire** | 후보자는 Hire 에 있다. Screen 은 판정 버튼을 갖지 않는다. |
| 평가 기준(rubric)·면접 대화·AI 점수·담당자 검토 | **Screen** | 면접 자체는 Screen 것. Hire 는 요약만 읽어 간다. |

연결 방향: Hire [AI 1차 면접 보내기] → Screen 이 면접 한 건과 링크를 만든다(Hire 후보자 id 를 같이 적어 둔다) → 후보자는 Hire 메일로 링크를 받는다 → 끝나면 Hire 후보자 상세가 Screen 에서 **요약(종합 점수·문항별 등급·검토 상태·리포트 링크)** 을 읽어 온다. Screen 이 Hire 를 가리키므로 **Hire 쪽 표는 바꾸지 않는다.**

**2026-09-26 순서:** SC1 ✅ → SC4 ✅ → SC4.5 ✅ → SC6 ✅ → **SC7 → SC8 → SC5**. SC2·SC3(Claude)은 키를 받는 대로 끼운다 — 채점 재료가 받아 적은 글이라 SC7 뒤라면 언제든 붙는다.

## 정할 것 (SC0 — 사용자)

1. ✅ **확정(2026-09-24): Hire 와 같은 프로젝트에 `screen_` 로 시작하는 표.** (SQL `supabase/screen-001-tables.sql`) — 추천 이유: 키를 새로 만들 필요가 없고 Hire 가 요약을 읽기 쉽다. 표 만들기는 늘 그렇듯 붙여넣고 Run 하는 SQL 한 덩어리로 드린다.
2. ✅ **정함(2026-09-24): AI 는 Claude. 붙이는 시점은 나중.** Claude 키 — 규칙상 **키는 제가 넣거나 연결하지 않습니다.** 사용자가 Vercel 환경변수 `ANTHROPIC_API_KEY` 에 직접 넣는다. 키가 없어도 Screen 은 돌아간다(채점은 "채점 대기", 후속 질문은 지금 규칙).
3. ⏸ **나중에 정함** (SC2 시작할 때). 모델·비용 — 면접 한 건에 Claude 호출이 약 (문항 수 × 후속 질문) + 채점 1회. 추천: 후속 질문은 빠른 모델, 채점은 가장 좋은 모델. 모델 이름은 코드에 박지 않고 설정값으로 둔다(지금 코드의 `claude-opus-5` 는 옛 이름이라 SC2 에서 같이 바꾼다).
4. ⏸ **받아 적기 서비스 — SC7 시작할 때 정함.** Claude 는 소리를 못 듣는다. 후보: OpenAI 받아 적기 · 네이버 CLOVA Speech · 리턴제로 · Google. 한국어 정확도·값·데이터가 어디서 처리되는지 비교해 추천하고, 열쇠는 사용자가 Vercel 에 직접 넣는다.
5. ⏸ **영상 저장 용량 — 보류(사용자 2026-09-26 "일단 제외"). 실측: 600kbps 녹화 4초 ≈ 0.25MB → 2분 ≈ 10MB.** 480p 로 찍으면 면접 한 건(5문항×2분) 약 40MB. Supabase 무료 저장 1GB 로는 수십 건이 한계라 실제로 쓰려면 유료 요금제(월 약 $25, 100GB)가 필요하다. 180일 자동 삭제가 용량을 지킨다.

## 저장할 표 (SC1 초안 — 실제 SQL 은 SC1 에서)

- `screen_jobs` — 공고(Hire 공고 id), 직무 설명, 질문·기준·비중 묶음
- `screen_interviews` — 추측 어려운 링크 토큰, Hire 후보자 id, 익명 라벨(후보자 A…), 상태(발급·진행·제출), 동의 시각, 만료
- `screen_messages` — 대화 한 줄씩(질문·답·후속 질문), 제출 후 수정 불가
- `screen_scores` — 문항별 AI 점수, 근거 문장, 이유, 모델, 규칙 버전
- `screen_reviews` — 담당자 수정 점수·메모·검토 상태(AI 점수는 덮어쓰지 않고 따로)

## V1 밖 (지금 안 한다)

- 표정·목소리 톤·억양·외모 평가 — 영상은 담당자가 보는 용도일 뿐, 설계 원칙상 채점하지 않는다
- AI 가 목소리로 실시간 대화하는 면접(Alex·Ribbon 방식) — V2 에서 검토(2026-09-26 사용자)
- AI 가 합불을 정하거나 점수순으로 줄 세우기 — 원칙상 하지 않는다
- 부정행위 감지(창 전환 추적 등), 다국어, 공고마다 다른 채점 모델
- 평가 기준 템플릿 공유 라이브러리

## 지켜야 할 것

- `ANTHROPIC_API_KEY` 는 커밋하지 않고, 제가 연결하지도 않는다. 키는 서버에만.
- Supabase 표 변경은 사용자에게 SQL 한 덩어리로.
- 후보자 화면에 평가 기준을 내려보내지 않는다. 점수에는 반드시 근거 원문이 붙는다.
- 영상·음성은 비공개 저장소에만. 공개 주소를 만들지 않는다. 보관 기간이 지나면 지운다.
- 직무와 무관한 개인 정보(나이·성별·가족·출신 등)는 질문에도 채점에도 쓰지 않는다.
