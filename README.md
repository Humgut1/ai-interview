# AI 면접 도구

미리 정한 **평가 기준(rubric)** 에 따라 1차 면접을 진행하고, 점수와 **그렇게 판단한 근거**를 정리해 사람이 검토할 수 있게 해 주는 도구입니다.

> 합격 여부를 정하는 것은 언제나 사람입니다. AI 는 점수와 근거만 제시합니다.

## 어떻게 쓰나요

```
① 인사담당자가 직무와 평가 기준을 만든다      ← 지금 구현된 부분
② 후보자에게 인터뷰 링크를 보낸다
③ 후보자가 링크를 열고 AI 와 채팅으로 면접을 본다
④ AI 가 기준대로 채점하고 근거가 된 답변을 함께 남긴다
⑤ 사람이 결과를 검토하고 최종 판단을 한다
```

## 설계 원칙

- **AI 는 합불을 결정하지 않는다.** 점수와 근거만 제시하고 판단은 사람이 한다.
- **모든 점수에는 근거가 된 답변 원문이 함께 저장된다.** 나중에 왜 그런 점수가 나왔는지 확인할 수 있어야 한다.
- **억양·유창성·성격은 평가하지 않는다.** rubric 에 적힌 내용만 평가한다.
- **후보자 화면은 불안감을 줄이는 방향으로 만든다.** 진행률 표시, 이어하기, 명확한 사전 안내.

## 진행 상황

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 | 평가 기준(rubric) 설정 화면 | ✅ 완료 (mock 데이터) |
| 2 | 후보자 인터뷰 채팅 화면 | ✅ 완료 (mock 데이터) |
| 3 | 결과 리뷰 리포트 화면 | ✅ 완료 (mock 데이터) |
| 4 | 디자인 시안 · UI 방향 정하기 | ✅ 시안 3개 (`/design`) |
| 5 | 대시보드 · 후보자 관리 | ⬜ 예정 |
| 6 | Supabase 스키마 · API 연결 | ⬜ 후순위 |

**API 연결은 일부러 뒤로 미뤘습니다.** 화면 구조와 보여 주는 방식이 먼저 정해져야 어떤 데이터를 어떤 모양으로 저장할지가 정해지기 때문입니다. 그래서 지금은 저장 버튼을 눌러도 실제로 보관되지 않습니다(임시저장은 브라우저에만 저장).

## 화면 구성 (계획 포함)

| 경로 | 설명 | 접근 |
| --- | --- | --- |
| `/jobs/new` | 직무 · 평가 기준 만들기 | 관리자 |
| `/jobs/[id]/edit` | 평가 기준 수정 | 관리자 |
| `/jobs/[id]/candidates` | 후보자 관리, 인터뷰 링크 발급 | 관리자 |
| `/jobs/[id]/compare` | 후보자 점수 비교 | 관리자 |
| `/interview/[token]` | 후보자 인터뷰 진행 | 링크(토큰)만으로 접근 |
| `/interviews/[id]` | 결과 리포트 | 관리자 |
| `/dashboard` | 직무 목록 · 요약 통계 | 관리자 |
| `/design` | 결과 화면 디자인 시안 3종 | 내부 확인용 |

## 1단계에서 만든 것

`/jobs/new` 한 화면입니다.

- 직무명 · 직무 설명 입력
- 질문 추가 / 삭제 / 순서 변경 (드래그 또는 ↑↓ 버튼)
- 질문마다 **우수 · 보통 · 미흡** 세 단계의 답변 기준 작성
- 질문별 **비중** — 정수로 입력하면 전체 대비 %를 자동 계산(합계는 항상 100%)
- 질문별 **후속 질문 최대 횟수** (0~3회)
- **직무 설명으로 질문 초안 만들기** — 현재는 정해진 초안을 돌려주는 임시 동작, API 연결 단계에서 Claude API 로 교체
- 저장 전 미입력 항목 검사, 임시저장(브라우저 보관) 및 이어서 작성

## 2단계에서 만든 것

`/interview/[token]` — 후보자가 링크만으로 들어와 진행하는 화면입니다. 로그인이 없습니다.

- **시작 전 안내 화면** — 질문 수, 예상 소요 시간, 진행 방식, 데이터 활용 동의 체크박스(동의해야 시작 가능)
- **채팅 진행** — 질문 하나씩, 진행률 표시, AI가 답변을 읽는 동안 로딩 표시
- **후속 질문** — 답변이 짧으면 정해 둔 횟수 안에서 더 구체적으로 되물음
- **제출 후 수정 불가** — 시작 전과 입력창 아래에 미리 안내
- **이어하기** — 창을 닫았다 같은 링크로 다시 들어오면 진행 상태가 그대로 복원됨
- **완료 화면** — 감사 인사와 다음 절차 안내

후보자 화면에는 **평가 기준(rubric)을 절대 내려보내지 않습니다.** 질문 문장만 전달합니다. 기준을 보고 답을 맞추는 일이 없어야 하기 때문입니다.

진행 상태는 지금 브라우저에 보관합니다(API 연결 단계에서 서버 저장으로 옮깁니다). 그래서 다른 기기에서 열면 이어하기가 되지 않습니다.

## 3단계에서 만든 것

`/interviews/[id]` — 담당자가 면접 결과를 검토하는 화면입니다.

- **종합 점수 + 한 줄 요약** — 질문 비중을 반영한 가중 평균
- **문항별 카드** — 질문 / 답변 전문 / AI 점수 / 채점 근거
- **근거가 된 발언 표시** — 점수의 이유가 된 문장을 따로 뽑아 주고, 답변 전문에서도 같은 문장을 형광펜으로 표시합니다. "왜 이 점수인지"를 원문에서 바로 확인할 수 있습니다.
- **담당자 점수 수정 + 메모** — AI 점수는 그대로 두고 수정값을 따로 보관합니다. 언제든 AI 점수로 되돌릴 수 있고, 종합 점수는 수정값 기준으로 다시 계산됩니다.
- **대면 면접용 추천 질문** — 문항마다 더 확인해 볼 질문
- **전체 트랜스크립트** — 오간 대화 전문
- **같은 직무 후보자 목록** — 일부러 점수순 정렬을 하지 않습니다. 줄을 세우는 순간 AI 점수가 합불처럼 읽히기 때문입니다.

이 화면은 담당자만 봅니다. 평가 기준(rubric)도 여기서만 보입니다. 검토 내용 저장은 아직 화면 동작만 있고, 실제 저장은 API 연결 단계에서 붙입니다.

## 4단계에서 만든 것

`/design` — 결과 리뷰 화면을 **어떤 모양으로 보여줄지** 세 가지 방향으로 만들어 두고 골라 보는 화면입니다. 담기는 내용(점수 · 근거 · 답변)은 셋 다 같고, 순서와 크기만 다릅니다.

| 시안 | 모양 | 이럴 때 좋습니다 | 대신 포기하는 것 |
| --- | --- | --- | --- |
| A 리포트형 | 한 장짜리 문서처럼 위에서 아래로 | 결과를 팀에 공유하거나 인쇄해서 회의에 들고 갈 때 | 점수 수정칸이 본문 사이에 흩어져 빠른 채점에는 불편 |
| B 작업대형 | 왼쪽 문항 목록 · 가운데 답변 · 오른쪽 채점 패널 | 채점 자체가 주된 일일 때. 점수 입력칸이 항상 같은 자리 | 화면을 3등분해 좁은 화면에서는 답답함 |
| C 스코어보드형 | 점수를 먼저 보여주고 근거는 펼쳐서 확인 | 하루에 후보자 여러 명을 훑어볼 때 | 숫자가 가장 크게 보여, 근거를 안 읽고 넘길 위험이 가장 큼 |

세 시안 모두 **점수 옆에는 반드시 근거가 붙어 있도록** 만들었습니다. 숫자만 크게 보여 주고 근거를 접어 버리는 화면은 후보자를 숫자로 줄 세우게 되기 때문입니다. 시안 화면의 점수 입력·저장은 동작하지 않습니다. 보여 주기 위한 화면입니다.

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:3000 을 엽니다.

환경변수는 `.env.example` 을 복사해 `.env.local` 로 만들어 채웁니다. 실제 키가 담긴 `.env.local` 은 git 에 올라가지 않습니다.

```bash
cp .env.example .env.local
```

```
                            VariantWorkbench, VariantScoreboard
  ui/                       입력 필드 등 공통 조각

  types.ts                  Job / Question / Criteria / 인터뷰 · 리포트 타입

```

## 기술 스택

Next.js (App Router) · TypeScript · Tailwind CSS · Supabase(예정) · Claude API(예정)

외부 UI 라이브러리는 쓰지 않고, 데이터는 ORM 없이 Supabase 를 직접 조회할 예정입니다.
